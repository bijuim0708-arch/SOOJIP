# 자동수집 연결 가이드

## v0.3 화면과 실제 수집기의 경계

HTML은 대구 관할 선택, 검토·분류·보고서 작성을 담당합니다. `collector/server.mjs` 로컬 서비스는 열린국회정보 국회의원 발의법률안 조회를 담당합니다. 다른 연결기는 아직 구현되지 않았습니다. API 키는 화면 파일이나 데이터 파일에 넣지 않고 로컬 서비스의 환경변수로만 주입합니다.

## 권장 처리 흐름

1. `sources.js`와 `official-sources.js`의 출처 고유 ID를 읽습니다.
2. 활성 출처 중 `verificationStatus`가 `공식주소확인`인 주소를 우선 연결합니다.
3. 연결기가 공개자료를 읽고 `connector-interface.js` 공통 형식으로 변환합니다.
4. 필수 필드, `regionIds`, 게시일시, 원문 URL을 검사합니다.
5. URL 정규화·제목 유사도·동일 인용문으로 중복 후보를 표시합니다.
6. 신규 자료는 반드시 `미확인` 상태로 수집함에 넣습니다.
7. 담당자가 원문을 확인하고 선택한 자료만 보고서에 반영합니다.

## 대구 지역 연결 순서

1. 열린국회정보 OpenAPI의 대구 지역구 의원 발의법률안 — v0.3 연결
2. 대구광역시의회와 9개 구·군의회 의사일정·회의록 — 미연결
3. 대구광역시와 9개 구·군의 공지·보도·행사
4. 등록 인물의 공식 블로그·유튜브·SNS
5. 뉴스 검색 API 또는 합법적인 검색 연동

## 저장·저작권 원칙

- 언론 기사는 제목·언론사·게시일·원문 링크를 기본으로 저장합니다.
- 기사 본문 전체를 복제하지 않고, 업무상 필요한 최소 발췌만 저장합니다.
- 같은 사안이나 동일 인용문은 중복 묶음으로 관리합니다.
- 발언자 식별이 불명확하면 구체적인 발언 요약을 만들지 않고 `검토필요`로 표시합니다.
- 회의록은 의회명·회기·회의명·안건·발언자·원문 위치를 함께 보존합니다.

## 업데이트와 백업

프로그램 교체 전 `자료 백업`으로 사용자 등록정보·검토상태·실제 수집자료·연결상태를 JSON으로 저장합니다. v0.3은 v0.1·v0.2 백업파일을 읽어 새 상태 형식으로 변환합니다. 변환된 사용자 인물·출처는 기본적으로 `대구광역시` 범위에 배치되므로, 복원 후 구·군 관할을 직접 보완합니다.

# 열린국회정보 국회 법안 연결 안내

## 연결 범위

- 공식 출처: 열린국회정보 OpenAPI
- 의원발의 법안 API: `국회의원 발의법률안`
- 법안 엔드포인트 ID: `nzmimeepazxkubdpn`
- 제안자 상세 API: `의안 제안자정보`
- 제안자 엔드포인트 ID: `BILLINFOPPSR`
- 대상: 대구 지역구 제22대 국회의원 12명

v0.3.4부터 국회 연결기는 두 경로를 제공합니다.

1. **대표발의 수집**: 대구 의원 이름으로 대표발의 법률안을 조회하고 각 `BILL_ID`의 제안자 상세를 보강합니다.
2. **공동발의 역검색**: 제22대 의원발의 법안 전체 목록에서 선택 기간의 법안을 추린 뒤 각 `BILL_ID`의 제안자 명단을 조회하여, 대구 의원이 공동발의자로 참여한 법안을 찾습니다.

두 경로 모두 정치적 평가나 위법 판단을 하지 않고, 열린국회정보의 공개 필드만 규칙 기반으로 정리합니다.

## 연결 진단

1. 열린국회정보에서 OpenAPI 인증키를 발급받습니다.
2. `collector/국회연결_진단.bat`을 실행합니다.
3. 표시되는 보안 입력창에 발급키를 붙여넣고 확인합니다.
4. 진단 결과에서 대표발의 단계와 공동발의 역검색 단계를 각각 확인합니다.

대표발의 정상 예시:

- `API mode : issued-key`
- `successful : 12`
- `proposer API : BILLINFOPPSR`
- `proposer enriched`가 반환 법안 수와 동일하거나 대부분 성공
- `proposer failures : 0`

공동발의 역검색 정상 예시:

- `reverse endpoint : /api/assembly/cosponsors`
- `recent candidates`가 0 이상
- 후보가 있다면 `proposer enriched`가 0보다 큼
- `matched bills`는 실제 대구 의원 공동발의 법안 수
- `reverse failures : 0`이면 정상

인증키는 실행 중인 프로세스의 환경변수에만 전달되고 진단 종료 후 제거됩니다. 키 값은 콘솔에 출력하거나 파일·GitHub·브라우저 저장공간에 기록하지 않습니다.

## 실제 서비스 실행

1. `collector/국회연결_정식키실행.bat`을 실행합니다.
2. 보안 입력창에 발급키를 입력합니다.
3. 검은 실행창을 닫지 않습니다.
4. `선이음-동향_실행.html` 또는 `index.html`의 출처 관리에서 연결 확인과 대표발의 동기화를 실행합니다.

서비스는 기본적으로 `127.0.0.1:3217`에서만 동작합니다. 실행창을 닫으면 키와 로컬 서비스, 메모리 캐시가 함께 종료됩니다.

현재 v0.3.4에서는 공동발의 역검색 백엔드 경로를 먼저 검증합니다. 화면 버튼 연결은 실제 인증키 검증 후 다음 단계에서 추가하는 것을 원칙으로 합니다.

## 대표발의 수집

경로:

`GET /api/assembly/sync?days=30`

동작:

1. 대구 국회의원 12명의 대표발의 법안을 각각 조회합니다.
2. 선택 기간 자료만 남깁니다.
3. 각 법안의 `BILL_ID`로 `BILLINFOPPSR`를 조회합니다.
4. 대표발의자·공동발의자 전체 명단을 법안 자료에 보강합니다.

`BILLINFOPPSR` 조회가 성공한 법안에는 다음 정보가 추가됩니다.

- 전체 제안자 수
- 대표발의자 수와 이름
- 공동발의자 수와 이름
- 제안자별 정당명
- 국회의원 코드
- 공동발의자 중 대구 관리대상 의원 여부
- 제안자 명단 100건 도달 시 목록 제한 가능성 표시

## 대구 의원 공동발의 역검색

경로:

`GET /api/assembly/cosponsors?days=30`

기간은 1~365일이며 기본값은 30일입니다.

동작 순서:

1. 제22대 `국회의원 발의법률안` 전체 목록을 페이지 단위로 조회합니다.
2. 선택 기간의 법안만 역검색 후보로 남깁니다.
3. 후보 법안의 `BILL_ID`를 `BILLINFOPPSR`로 조회합니다.
4. 대표발의자를 제외한 제안자 중 대구 지역구 의원 12명과 일치하는 의원을 찾습니다.
5. 대표발의자가 대구 의원인 법안은 기존 대표발의 수집과 중복되므로 역검색 결과에서 제외합니다.
6. 한 법안에 대구 의원 여러 명이 공동발의한 경우 하나의 자료에 여러 관련 인물을 연결합니다.

역검색 결과는 다음 원칙으로 생성합니다.

- `type`: `법안 공동발의`
- `status`: `미확인`
- `dataOrigin`: `official_api`
- `verificationStatus`: `API응답+제안자정보`
- `apiMeta.matchBasis`: `BILLINFOPPSR 공동발의자 일치`
- `apiMeta.reverseScan`: `true`

## API 호출량과 캐시

공동발의 역검색은 대표발의 수집보다 API 호출량이 큽니다. 따라서 기존 대표발의 동기화와 별도 경로로 분리합니다.

- 제22대 의원발의 전체 목록: 프로세스 메모리에서 6시간 캐시
- `BILLINFOPPSR` 제안자 상세: 프로세스 메모리에서 24시간 캐시
- 제안자 상세 동시 요청: 낮은 동시성으로 제한
- 역검색 기간 상한: 365일

캐시는 파일에 저장하지 않으며 실행창을 닫으면 사라집니다.

## 자료 검토

- 새 자료는 `미확인` 상태로 들어갑니다.
- 자동 문장은 API 필드를 조합한 규칙 기반 요약이며 AI 요약이 아닙니다.
- 상세 링크에서 국회 원문을 확인한 뒤 `원문 확인` 또는 `보고서 반영`을 선택합니다.
- 대표발의 조회 또는 제안자정보 조회가 일부 실패하면 성공 자료는 유지하고 실패 내역을 별도로 표시합니다.
- `BILLINFOPPSR` 목록이 100건에 도달하거나 전체 건수보다 적게 반환된 경우 전체 제안자 명단 제한 가능성을 염두에 두고 원문을 재확인합니다.
- 공동발의 여부는 이름 추정이 아니라 `BILLINFOPPSR` 공개 제안자 명단 일치로만 판정합니다.

## 오류 확인

- `연결할 수 없습니다`: 실행창이 열려 있는지, Node.js 18 이상인지 확인합니다.
- `ERROR-290`: 인증키가 유효한지 확인합니다.
- `HTTP 502` 또는 `국회 API 수집 실패`: 인터넷 연결, 인증키, 열린국회정보 서비스 상태를 확인합니다.
- `proposer failures`: 대표발의 법안은 수집됐지만 `BILLINFOPPSR` 제안자정보 조회 일부가 실패한 경우입니다.
- `reverse failures`: 공동발의 역검색 후보 중 일부 법안의 제안자정보 조회가 실패한 경우입니다.
- `matched bills : 0`: 선택 기간에 대구 의원이 다른 의원 법안에 공동발의자로 참여한 자료가 없을 수 있습니다. 이것만으로 오류를 의미하지 않습니다.
- 포트 충돌: 환경변수 `SUNEUM_COLLECTOR_PORT`를 바꾸면 화면의 기본 주소와 달라지므로 기본 포트 `3217` 사용을 권장합니다.
